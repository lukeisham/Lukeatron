# Constructed examples: how to write them

How the AI-written example of a device is written.

A constructed example is one the AI writes itself. Every device has exactly one, and it lives alongside the device's one real quote (`quotes.md`, step 1); it is not a stand-in that goes away when a real quote is found. It follows the same Test 2 floor. These rules apply to any device, Flipsides included.

0. **One per device.** Each device has exactly one constructed example. A device with none gets one written; a device with two keeps the one that best meets steps 1 and 2 below, and the other is removed only with Luke's say-so, because that deletes a stored example.

1. **Illustrate the definition exactly.** Write from the device's definition, and check that definition first if it has not been verified (`definitions.md`, step 2). Every part of the definition must be visible in the example, doing the job the definition names. The example must be that device and no other, and a reader who did not know its name could identify it from the example alone.
2. **Put the part the device depends on in italics.** If the device turns on a particular word, syllable, letter, sound, word ending, word order or punctuation mark, wrap exactly that part in `*asterisks*` and nothing else; for example, the repeated opening letters in Alliteration (`*P*eter's *p*roud *p*ursuit`), the matching word-endings in Homoioteleuton, the word with two senses in a Pun, the repeated word where one clause ends and the next begins in Anadiplosis. Italicise the smallest piece the device actually depends on: a letter or syllable when the device works at that level, a whole word when it works at that level. Where the device depends on a structure that spans the sentence (a mirrored pair in Chiasmus), italicise each part of the structure. Where it depends on no particular piece (a fallacy whose whole argument is the error), use no italics. The app reads a single pair of asterisks as italics, so never nest them and never use a literal asterisk for any other purpose.
3. **Fallacies and Flipsides.** A fallacy example commits the error as an argument and does not merely describe it. A Flipside example shows the same move without the fault, with the evidence or reasoning visible (`definitions.md`, step 7).
4. **One example, one device.** Do not let a second device carry the example. If the sentence also happens to contain another figure, either leave it unremarked or change the wording so that it does not.
5. **Self-contained and short.** It works without surrounding text. Use the shortest wording that still meets steps 1 and 2. At most one short closing parenthesis, which may name the moving parts or say which sense is meant, and which must never supply the device itself.
6. **Do not pass it off as a quote.** Credit it to no one and give it no date: `attribution` is `Unattributed`, there is no `"date"`, and the parenthesis names no work, no date and no locator, and never says "trans.". Write a word it glosses in plain quotation marks inside the parenthesis, never in italics ("the word \"own\" only adds emphasis"): `quotes.py` reads an italic, a digit or "trans." in the closing parenthesis as a citation and would list the example in the Index as a real quote. `seed.quote_status` treats a parenthesis that cites a work as a sign of a real quote, so a citation-shaped parenthesis on a constructed example would make the device look as if it already had a real quote and hide it from the list of devices still needing one.
7. **Clean content.** No swear words and no sexual content; choose different wording. English only; if the device depends on another language (case endings, a foreign pun), do not construct an example, because a real quote with a translation is the only valid one (`quotes.md`, step 4).
8. **Check before writing it in.** Put the definition and the example side by side and tick each part of the definition against the example. Check the italicised parts against the device: letters and word endings by counting them, a repeated word by reading the sentence aloud. If any part is missing or extra, rewrite.
9. **Where it is written, and after.** Same as `quotes.md`, steps 7 and 9: add to `seed/devices.json` and the row in `rhetoric.db` (no rebuild), commit first (see `change-workflow.md`), run the tests, log a row in `app-decisions.md`, and re-score the device if its Test 2 result changes. The constructed example stays beside the real quote. When a definition is edited, re-check its constructed examples against the new wording.
