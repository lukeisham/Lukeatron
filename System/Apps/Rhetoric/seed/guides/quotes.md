# Examples and quotes: how to find and add them

How a real quote is found, checked and written in.

These rules apply to any device; Flipsides have their own rule (step 5).

1. **Prefer a real quote.** The scope is as wide as can be: anywhere a quote can be found and verified, including non-fiction, fiction, film, poetry, speeches, history, things fictional characters say, folk sayings, riddles and songs. A device keeps exactly one real, credited quote and exactly one AI-generated (constructed) example, side by side (see `constructed-examples.md`). Add the quote beside the constructed example. If the device already has a real quote and the new one is a cleaner match, the new one replaces the old real quote, once the new one has been checked. The constructed example is never removed because a real quote was found, and a real quote is never removed to make room for a constructed one. Do not invent a quote to fill the gap.
2. **It must match the device cleanly.** Test 2 (see `confidence-rubric.md`) is the floor: a reader who did not know the device's name could identify it from the quote alone. Above that floor, aim for the best match available:
   - **Whole definition.** Every part of the definition is in the quote, doing the job the definition names. A quote that contains a word or a related trick but not the defining move does not count.
   - **Main trick.** The device is what the quote is built on, not something incidental that happens to appear in a longer sentence.
   - **Stands alone.** It works without the surrounding text. At most one short parenthesis may name the quote's moving parts (for example which sense of a word is meant), but the parenthesis must never supply the device itself. If the reader needs a note about the author's name, the age or a pun in another language to see it, it fails.
   - **Cleanest instance.** Among candidates, take the most standard, handbook-style instance over a more famous but looser one.
   - **Fallacies and Flipsides.** A fallacy quote commits the error as an argument and does not merely describe it. A Flipside quote shows the legitimate use, with its evidence or reasoning visible.
   - **Check the fallacy's definition first.** Search results and example lists often put the wrong label on a fallacy. Before judging a quote against a fallacy or Flipside, check the fallacy's definition in a second named source (for example the Internet Encyclopedia of Philosophy, the Stanford Encyclopedia of Philosophy or Purdue OWL) and confirm it agrees with the definition in the database. Never rely on a search summary that calls something an example of the fallacy.
   - **No swear words or sexual content.** Do not use a quote that contains swear words or sexual content, even when it is otherwise the best match. Do not clean it up either, because an altered quote is no longer a verified quote; choose another. Other offensive material, such as hostile views or propaganda, is allowed where it is the best verified match, and the `app-decisions.md` row should say so.
   - **Shorter is better.** Use the shortest passage that still meets every point above: cut lead-in and trailing sentences, and join non-adjacent parts with an ellipsis. Between two quotes that match equally well, take the shorter.
   - **Several senses.** If a device has more than one sense or kind, the quote shows one of them, and the parenthesis says which.
   - **When no clean match is found.** Search properly first (several works and kinds of source). Only then add the closest quote, and flag it as a loose fit (step 8). A loose quote is a placeholder, and the cleaner quote replaces it when one turns up.
3. **Check it against a text before adding it.** Find the work itself (full text, an official transcript, or a reputable edition or scan) and confirm the wording, the speaker and a locator (chapter, scene, date). For plays, epics and books, use the numbering of the Project Gutenberg text. A search summary, a quotation site or memory is not a check. For a song, check the lyric against the recording's official lyrics or liner notes. For a folk saying, riddle or other common saying, which has no single author, show that it is common: it appears in at least two independent named collections or dictionaries of proverbs (or the equivalent), and give the earliest attested form found. If a known author or origin turns up, credit that person instead. If only an anthology excerpt or a transcript on a secondary site can be found, say so in the `app-decisions.md` row.
4. **Translations.** Prefer a named translator whose wording you have read, in the body (for example "trans. Yonge"). If no such translation can be used and the device exists in another language (the figure depends on that language, such as Latin case endings), an AI translation is fine, provided you have verified that the device really exists in that language: find the original text, and a source that names the figure for that language. Say in the parenthesis that the English is by Claude (AI). Never translate it yourself and credit someone else. Note any spelling that was modernised.
5. **Flipsides.** The aim is a real, verified quote for every Fallacy Flipside, however long finding them takes. Every Flipside label is coined for this app, so no source gives a ready-made example, and each quote must show the legitimate use, not just the fallacy. A Flipside's constructed example stays, and the real quote is added beside it (step 1: one real quote and one constructed example per device). Say in the `app-decisions.md` row that the example is for a Flipside.
6. **Credit and date.** `attribution` is the person the words are credited to ("Winston Churchill"). For a fictional character's words in a book, play or poem, credit the author or writer and name the character in the example text; for a character in a film (or other screen work), credit the character by name ("Maximus"), because screenplay credit seldom says who wrote a line, and give the film and year in the closing parenthesis; for a song, credit the songwriter; for a folk saying, riddle or other verified common saying, use `Unattributed` and give the earliest source in the example text. The work and passage go in the example text, in a closing parenthesis, with titles in `*italics*`. Do not write "attributed to". Use `Unattributed` only when no credit is held (as with verified common sayings, folk sayings and riddles).
   **Date.** If it can be found quickly, record when the words were first said or published, as the optional `"date"` on the example in `seed/devices.json` (the database's `quote_date`): `YYYY-MM-DD` for a speech, broadcast, letter or dated article, `YYYY` for a book or poem. Do not search for it. Take it from the source already read for step 3, or from what the closing parenthesis already states, and give up after one quick look; an unknown date is left out, and the Index lists the quote as "Date unknown". Never guess, and never store an approximate date ("c. 1600"): the column accepts only a year or a full date. A year under 1000 is written with four digits (`0060` is AD 60) and a year BC with a minus sign (`-0935` is 935 BC, with no year 0); the Index shows them as "AD 60" and "935 BC" and groups them as "AD 60s" and "930s BC". Exception: for the books of the Bible, Shakespeare's plays and other ancient or medieval works, whose dates are scholars' estimates, store a single year and say in the `app-decisions.md` row that it is an estimate. Bible: conservative scholarship's date of writing. Plays: the composition year, not the First Folio's 1623; Sonnets: the 1609 printing. Other works: the date Wikipedia gives, and where it gives only a range, the midpoint of the best-attested one (*Beowulf*: the manuscript's AD 975 to 1025, so `1000`; the Code of Hammurabi: c. 1753 BC, so `-1753`). Use the date of the original, not of a translation, an edition or a later book that quotes it (a credit's "1937" for a translation or "1898" for the work that listed the quote is not the quote's date). A constructed example has no date.
7. **Where it is written.** Add the example to `seed/devices.json` and insert the row into `rhetoric.db` as well; do not rebuild the database, because a rebuild discards Luke's Topical Types. Commit first (see `change-workflow.md`) and keep the JSON in its existing layout (one-space indent, no escaping of non-ASCII), so a diff shows only the new examples. If an example has a `"date"`, run `python3 -m seed.add_quote_date` as well: it writes the dates from `seed/devices.json` into the live database, matching by device name and example text.
8. **Say when the fit is loose.** If a quote falls short of any point in step 2, name the point in the `app-decisions.md` row (for example "the transition announces little about what follows") instead of leaving it unremarked.
9. **After the change.** Run the tests, log a row in `app-decisions.md` (devices, sources, any quote replaced, new example, credited and dated counts, and the commit that holds the pre-change state), and re-score the device if the new example changes its Test 2 result.
10. **Finding devices that still need a quote.** Do not judge by the credit alone, because a real quote with an anonymous author (such as the *Rhetorica ad Herennium*) is stored as `Unattributed`. A device has a real quote when an example is credited **or** its closing parenthesis cites a work: an italic title, a date or locator, or "trans.". A constructed example's parenthesis only explains it. `python3 -m seed.quote_status` (run from this folder, read-only) lists the devices with no real quote, and `--draw 5 --seed <n>` gives a repeatable random draw of five.
