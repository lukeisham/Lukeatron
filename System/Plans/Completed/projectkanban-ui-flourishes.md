# Plan — ProjectKanban: small attention-focusing flourishes (Next tag, copy wash, saved/failed edit feedback)

## Objective
Add three small, motion-safe UI flourishes to the Dashboard (`System/Apps/ProjectKanban/_template/app/`) so the interface reflects how the app already focuses attention — the top open row is visibly the **Next** action, whatever Luke just **copied** briefly acknowledges itself, and a **saved or failed edit** answers on the field he touched — without changing any behaviour, data, speed or safety. This specialises the Lukeatron North Star ("extend it deliberately, never by accident"): every value is a token in `tokens.css` (StyleGuide.md's one rule), nothing new is invented outside it, and Luke signs off the feel before it ships. Design source: the clickable specimen built and approved in the 2026-09-20 session (Luke's calls: **keep the ⚑ glyph as it is; the top row gets a small "Next" word; saved edits get a flourish**).

## Success criteria (measurable)
- **Next tag.** At most one visible "Next" word appears on a project page (none when the project has no open actions) — on the first open row in file order (the same row `model.py:522` exposes as `next_action`); never on done rows; present on a linked row if that row is first. The row also gets a lane-coloured left edge, a faint tint and heavier label text. The ⚑ badge is untouched: `test_project.mjs`'s existing lane-source tests (`⚑`, line ~590) pass unchanged.
- **Meaning not carried by colour or motion alone.** The "Next" word, the "Copied" text, the ✓ mark and the persistent failed-state text all remain readable with animation off.
- **Copy.** On a successful copy, the thing copied (a task row, a section's list, or a board card) washes in the accent colour and fades; the button reads "Copied" (the existing assertion at `test_project.mjs:321` stays unchanged, so the ✓ is added by CSS, not by changing the text) for the existing 1.2 s. The **board card's copy button, which today gives no confirmation at all**, gains the same. A failed copy shows no wash. Clicking a card's copy button still never opens the project.
- **Saved edit.** After a successful edit (due, owner, lane) the page re-renders as today, then the edited control gets a brief accent wash and a ✓, applied once and never replayed by later re-renders (toggle-done, decision-log toggle). If the edit moves the row (e.g. a new due date), the flourish follows the row.
- **Failed edit.** The control that failed turns red and *stays* red (no fade) until the next input on it; the existing error banner and plain-English sentence (`edits.js`) are unchanged.
- **Tokens only.** New tokens live in `tokens.css` only — `--motion-flash`, `--danger`, plus a wash-strength and a next-tint-strength token — defined for default, dark (both twin blocks, identical), paper, and print; `--motion-flash` is zeroed by the existing `prefers-reduced-motion` block. No literal colour, size or duration appears in any consuming CSS file (the specimen's `.06em`, `800ms`, `18%`, `9%` all become tokens; the ✓ mark is positioned from the control's measured box instead of `1.3em`).
- **CSS-1 respected.** `task-row.css` (184 lines) and `project.css` (171) are already over the ~150-line cap, so all new rules go in a **new** `app/shared/flourish.css` (shared, not `project/`, because the board card uses them too; linked from `index.html` after `task-row.css`), with a header listing the exact tokens it needs.
- **Contrast.** `python3 check_contrast.py` passes with the new pairs added (`--danger` text on `--bg`/`--panel-bg`; the Next row's ink text on each of the five lane tints, and the washes' ink text) in default, dark and paper, plus print — every ratio ≥ 4.5:1 (≥ 3:1 for non-text borders).
- **Speed and safety.** Animation is CSS-only; no new network calls, no timers on the input path, no layout shift (bounding boxes of the row and its neighbours identical before and after a flourish, measured live); no existing confirmation, disabled state or error path is removed or delayed.
- **Print is clean.** Printing a project page shows no wash, no animation and no tinted Next row (checked in `flourish.css`'s print rule and in a print preview).
- **Live registries never written during verification.** a checksum of every file under `Memory/Medium-Term/Projects/` is identical before Step 9 and after it (`git status` cannot guard this: `Memory/` is not tracked by git). Saved/failed-edit checks run against a copy of the Projects data on a second server instance, never the live `:8789` data (fallback in Step 9 if that isn't possible).
- **Tests.** Full suite (`test_board.mjs`, `test_controls.mjs`, `test_project.mjs`, `test_reorder.mjs`, `python3 -m unittest discover` from `_template/`) shows 0 new failures against the baseline written into this plan's **Notes → Baseline** in Step 1, plus new cases for each behaviour above.
- **Luke's sign-off.** Luke has seen it live in all three palettes and approved the feel; his approval and the final values chosen (wash length, tint strength) are recorded in this plan's **Notes → Sign-off** in Step 10. Any tuning changes tokens only.
- **Docs.** `StyleGuide.md` gains the new tokens and a short "flourish rules" section; `refactor-registry.md` gets one dated Migration-log row. `wishlist.md` gets no row (built items are deleted, never added-then-marked-built; this was never filed there).
