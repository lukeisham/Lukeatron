# Isotype / Otto Neurath pictorial statistics
**Tags:** data-viz
**Anti-patterns / Avoid:** never represent quantity by resizing, rotating, tilting, adding interior detail/outline/gradient to, or unevenly spacing a pictogram — quantity is shown only by repeating identical flat silhouettes on a shared baseline, colour never encodes magnitude, and a legend without an explicit unit statement is incomplete.
**Visual DNA:** Standardised, orthogonal pictogram silhouettes convey quantity by *repetition* of an identical icon, never by resizing one icon — flat single-colour figures, strict grid alignment, built for universal, language-independent legibility. A "transformer" role (originated by Marie Neurath) maps real quantities to symbol counts, so every chart's unit ratio stays internally consistent.
**Signature tells (must be visibly present):** 1) quantity shown only by repeating an identical unscaled icon, never by resizing/stretching one symbol 2) flat single-colour silhouettes with zero interior line, outline, or gradient — every icon is a solid unmodulated shape 3) strict orthogonal grid alignment on a shared baseline, with an explicit "icon = N units" key statement rendered directly in the image.
**Craft-rule carve-outs:** this style is deliberately sparse and legitimately sits below skill.md's detail-budget floor by design — the pictogram principle (clarity through repetition of a simple silhouette, not density) overrides the generic minimum drawn-element count; do not pad a chart with extra ornament to hit the floor. It also legitimately uses bare geometric primitives (circles, rectangles) for icon construction rather than hand-built Bézier organic forms, since standardised, instantly-legible silhouettes are the point — this overrides the generic "Bézier over primitives" rule for this style specifically. The pictograms are also unlit flat silhouettes with no interior modelling, so skill.md's one-global-light and contact-shadow rules do not apply — add no light-direction comment, no gradients and no contact shadows; a shadow under an icon would read as a second countable unit and corrupt the chart.
**Typical subject / composition:** any countable comparison for an ORIGINAL dataset (populations, production, survey results, resource counts) — rows of identical pictograms grouped by category; the subject is the data, never a decorative scene.
**Standard layers (z-order, bottom → top):**
- `<g id="grid-baseline">` — layout metadata only (row baselines, column positions); never rendered — no gridlines or axis lines appear in the output, since categorical row labels are sufficient
- `<g id="pictogram-rows">` — one sub-group per data category/row
- `<g id="unit-icon-repeats">` — the repeated identical icon instances representing the quantity within each row, terminating in a clipped fractional icon where the value is not a whole multiple of the unit
- `<g id="axis-labels">` — row category labels, flush-left
- `<g id="legend-key">` — the unit/key statement (see technique below)
- `<g id="title-caption">`
**Distinctive SVG techniques:**
- Quantity by repetition: build each category's icon once as a `<symbol>` in `<defs>`, instance it with repeated `<use>` elements — a value of 7 is seven `<use>` calls, never one icon scaled up.
- Construction: silhouette only (no interior line, no outline, no gradient), uniform flat mass, built on a modular grid, roughly 3–7 strokes' worth of visual complexity per figure, aspect ratio close to 2:3 or square, strictly orthogonal — no arbitrary rotation.
- Fractional icon: CLIP, never scale. Wrap a `<clipPath>` containing a `<rect x="0" y="0" width="{fraction * iconWidth}" height="{iconHeight}">` around a `<use>` of the same `<symbol>`, so the partial icon is full-height but truncated left-to-right at the fractional proportion — e.g. a row value of 5.4 units on a 4-per-row wrap renders four full icons plus one icon clipped to 40% width. Prefer rounding to avoid fractions where practical; if more than roughly a quarter of a chart's rows need a partial icon, the unit is too large — choose a bigger unit instead.
- Key/unit statement: one full-size icon rendered at the same scale as the data rows, immediately followed by a declarative equals statement in cardinal numbers — e.g. "= 1,000,000 persons" — with no narrative framing. Place it below the last row or top-left, visible before the data rows are read; on a 1080-wide canvas, set the icon at the row's icon height, the equals text at 22–26px, in `#000000` or the icon's category colour, left-aligned to the icon.
- Layout: icons sit on a shared optical baseline per row; row-to-row leading is 1–1.5× icon height; horizontal gap between icons is 2–4 units of the icon's own module width, with icons chunked in groups of 5 or 10 separated by a slightly larger gap between groups; row labels flush-left in small caps or lowercase sans.
- Colour encodes category only: each category gets one flat hue, applied uniformly to every icon instance in its rows; a second hue used together with the base colour (via the superimposition technique below) buys a second categorical dimension, never a magnitude ramp.
- Superimposition (Vienna Method): a base icon plus a smaller overlay icon at 30–40% of the base icon's scale, placed top-right or bottom-right of the base, adding a second attribute to the same figure; never stack more than two layers this way.
- Descendants: the silhouette-plus-grid principle passes directly into Otl Aicher's Olympic pictograms and the AIGA symbol signs — both are legitimate references for icon construction, not for this chart layout.
**Palette:** flat category hues — black `#000000`, red/rust `#CC3333`, blue `#3366CC`, green `#669944`, ochre `#CCAA66` — on a white `#FFFFFF` ground; default to monochrome black-on-white and add a second hue only for a genuine second category.
**Typography:** geometric sans, regular weight only (hierarchy comes from size, never bold); stack `Futura, "Century Gothic", "Trebuchet MS", sans-serif`; lowercase preferred for row labels, small caps for category headers; flush-left or centred, never justified.

**Choosing this over its neighbours:** against `minimal-geometric-logo.md` — Isotype exists to compare DATA: it repeats an identical icon across rows so a viewer can count/compare magnitudes, and never has fewer than several instanced icons; minimal-geometric-logo is a single standalone identity mark built from 2–5 load-bearing primitives with no repetition and no data behind it. Against `nigel-holmes-explanation-graphics.md` — Holmes builds one pseudo-3D metaphor object or mechanism walked through by numbered arrows and can use colour, humour, and simplified depth to hook a general reader; Isotype stays strictly flat, orthogonal, and colour-coded by category only (never by magnitude), with the data literally counted in repeated silhouettes rather than illustrated as a scene. Choose Isotype specifically when the deliverable is a countable comparison across categories, not a single mark or a narrated mechanism.
